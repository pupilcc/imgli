# OCR 敏感词表维护约定

imgli 图床的 OCR 词表**不进业务仓库正文**（避免公开仓误存真实敏感词）。  
运营侧建议单独仓库或私有文件维护，经 Admin「系统设置 → OCR 词表审核」导入。

OCR 旁路服务的部署与访问控制见 `deploy/ocr-paddle/README.md`。

## 格式

```text
# 注释行
违禁词示例
another-term
```

- 每行一词  
- `#` 开头为注释  
- 保存/导入时 trim、去空行、大小写不敏感去重  

Admin 支持：

| 操作 | 说明 |
|------|------|
| 导入合并 | 与现有词表去重合并 |
| 导入替换 | 用文件内容整体替换编辑框 |
| 导出 .txt | 下载当前编辑框词表（带头注释） |

## 推荐私有仓库结构

```text
lexicon/
  README.md           # 收录原则、排除原则
  core.txt            # 高置信：命中 → 待审/拒绝
  experimental.txt    # 试运行候选（人工筛后再并入 core）
  CHANGELOG.md        # 版本说明
```

**收录原则**

- 只收与图床滥用相关的高置信表达（短语优先，≥3 字）  
- 过短/过泛（2 字常见词）不进 core，避免误杀  
- 每条变更可说明来源（自建 / 举报 / 开源候选筛入）  
- 烟雾测试词（`BAILIOCRSMOKE999` / `hello` / `TESTWORD`）验收后立即删除  

## 开源词表怎么用

1. **可以**把公开敏感词列表当**候选源**  
2. **不要**整包盲导入上线  
3. 人工筛进 `core.txt` → Admin「导入合并/替换」→ 保存  

政恐相关：**开源列表 ≠ 合规**；OCR+词表只覆盖「图上有字」一类，需配合人审与（如需）云审。

## 上线流程

1. 编辑私有 `core.txt`  
2. Admin → OCR 词表 → 导入 → 检查词数 → 保存设置  
3. 审核队列看 `ocr_keywords · hits=…` 调词表  

运行时权威词表在 settings `moderation.ocr_keywords.keywords`(DB);`core.txt` 只是运维侧私有副本,建议服务器上 mode 600 存放。
